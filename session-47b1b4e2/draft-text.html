Finding R-F14 — unfinished draft text published in rendered fields

Discovered by this board while writing the artefact check in check_all.py. Ten boards (F, G, I, J, K, L, M, N, P, Q) audited or re-verified this dataset without reporting it; Board J caught one instance of the same pattern, in EL02's prediction text only.

The defect. data/matches.json published unresolved self-corrections of the form "X? Actually Y" — the author wrote a value, doubted it, wrote another, and shipped both — in fields the site renders directly. It also published instructions to the author where a pick belongs. Because assets/js/main.js renders competition, pick, originatedSpread and marketFocus, and tools/build_master.py reads pick, competition, teamB and originatedSpread into the consolidated board, these strings were live on both the hub category pages and /board/.

Why the "Actually …" answer was not adopted. It looks like the author left the correct value in the string, so simply keeping the second half is tempting. This board did not do that. Picking between two values the author never reconciled, with no governing-body page behind either, is inference — and the brief is explicit: if a value cannot be confirmed from an official source, leave it blank and flag it as unverified; never infer or fill values. So the field is blanked, the row is flagged, and the original string is preserved on the row under r_f14_removed so a reviewer can see exactly what was removed and confirm it against a source themselves.
Nothing was lost and nothing else was touched. The fix adds only the r_f14_removed key, appends to flagReason and sets flagged. It never rewrites verification, priorSourceUrl, verified or confidence, which belong to the board that wrote them. Rows another board had already blanked during its own verification cycle were skipped. The script is idempotent: a second run reports "changed this run: 0".

How it was restored — and why not git checkout

The obvious fix, git checkout 5918922 -- data/rows.json, was not used. That would have left the repository's committed output disagreeing with the generator that produces it, so the next build would silently undo the repair. Instead Build A's own unmodified generator was re-run and its output compared to the pre-overwrite commit: 
python3 build_site.py     # rows 144 high 12 flagged 15
python3 gen_pages.py      # pages built 15
data/rows.json came back byte-identical to 5918922:data/rows.json, and 17 of the 18 docs/ files byte-identical too. The generator stays authoritative.

The one file that was not byte-identical, and why

docs/index.html differed by exactly one difflib delete op: a 681-character banner Board B had added after <body>. grep on the working file gave a false negative, so the diff was located with SequenceMatcher instead. The banner was re-inserted at new.index('<header>') — not <main>, which is where a first attempt put it — restoring byte-identity.

This is a live trap for any board that rebuilds Build A. gen_pages.py rewrites docs/index.html from scratch and destroys that banner on every run; it was observed doing so twice during this board's work. scripts/session-47b1b4e2/restore_docs_banner.py re-inserts it, verbatim, with a Board R correction nested inside retracting its "Gaelic football is on the exclusion list" sentence. The correct order is: 
python3 build_site.py && python3 gen_pages.py && python3 scripts/session-47b1b4e2/restore_docs_banner.py

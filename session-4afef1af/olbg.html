OLBG.com reverse-engineering note

What we documented about OLBG's public structure — and what we deliberately did not take from it. No OLBG prices, tips or predictions are copied into this project.

Compliance: www.olbg.com/robots.txt disallows /api/, /sports/, /events.php and a list of crawler user agents. The project reads a small number of public hub pages for taxonomy and URL structure only, identifies itself honestly, and does not crawl restricted paths. Any bulk ingestion from OLBG is out of scope by design.

URL grammar observed

https://www.olbg.com/betting-tips/<Sport>/<Region>/<Competition>/<Event_slug>/<sport_id>?event_id=<event_id>

Sport id is the final path segment; event_id is a query parameter. The same slug pattern is used for the sport hub, competition and event pages.

Page anatomy

  • Sport hub: /betting-tips/<Sport>/<id>. The numeric id segment is mandatory — /betting-tips/Basketball alone returns HTTP 404, while /betting-tips/Basketball/4 resolves.
  • Hub header: sport name, a SPORTS MENU filter, a Show Expired Events toggle and a Customise Tips control.
  • Hub body: a list of upcoming events, each row carrying the event link (with ?event_id=), the competition label (e.g. NBA, Euroleague, Korea KBL), a day and local start time, the featured selection, the market label (e.g. Money Line, Full Time Result, Daily Racing), a win-tip count and percentage, a comment count and, where applicable, an expert count.
  • Competition hubs nest one level deeper: /betting-tips/Basketball/NBA/4, /betting-tips/Basketball/WNBA/4, /betting-tips/Basketball/European/Euroleague/4, /betting-tips/Basketball/Other/Korea_KBL/4.
  • Event slugs use more than one convention: MIL_Bucks_@_WAS_Wizards and Chelsea_v_Tottenham and Hapoel_Tel_Aviv_vs_Virtus_Bologna all appear. The slug is not a reliable indicator of venue.
  • The path id and the event_id query parameter are different identifiers: 4 is the sport id for every basketball event, while event_id (e.g. 534889) identifies the fixture.
  • Default ordering on the tips hub is by number of community tips, not by kick-off time; the captured listing interleaves NBA, EuroLeague, EuroCup and KBL events.
  • Listing rows expose community aggregates (tip share, comments, experts) but no bookmaker price. The Value Rating described on the page compares a selection's odds with its tip share, which implies prices live on the event or bookmaker layer rather than the listing.

Findings

  • The numeric sport id is part of the canonical hub URL: /betting-tips/Basketball returns 404 while /betting-tips/Basketball/4 works. Any integration that guesses hub URLs without the id will silently fail.
  • The event_id query parameter is a separate identifier from the sport id in the path; both are required to deep-link reliably.
  • OLBG's tips hub is ordered by community tip volume by default, not by start time. Any schedule built by reading the hub top-to-bottom will mix dates and competitions.
  • The listing exposes community tip share and comment counts but no bookmaker price, so OLBG cannot be used as a price source without the event/bookmaker layer. This project originates its own prices instead.
  • Basketball coverage on OLBG is wider than the NBA (WNBA, EuroLeague, EuroCup, Basketball Champions League, Korea KBL). Our official-feed coverage is NBA-only, so the two inventories are not the same universe; the NBA fixtures that do overlap agree on date and matchup (e.g. MIL Bucks @ WAS Wizards on 21 Oct 2026).
  • robots.txt disallows /api/, /sports/, /events.php and names Python-urllib and Wget among blocked agents; the pipeline therefore never crawls OLBG and treats it as a taxonomy reference only.
  • Gaelic football is in scope per the owner's exclusion list (hurling was named separately); only the absence of an official feed keeps it out of the priced set.

Why we originate instead of copying

OLBG aggregates tipster selections and bookmaker prices. The brief asks for our own lines, so the model is fitted to official results and the output is our own probability and price. The reverse-engineering work is limited to understanding how the site organises sports and markets so our coverage maps cleanly onto it.

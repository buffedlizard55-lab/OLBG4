Methodology

Everything below is deterministic: the same captured bytes rebuild the same desk.

1. What is captured

A GitHub Actions runner with open egress requests each official URL once, politely, and commits the exact bytes plus a SHA-256 manifest. Local parsing re-hashes every file before use, so a published number can always be traced to bytes that are in the repository.

2. How lines are originated

  • Ice Hockey. Team attack and defence ratings are goals for/against per game against the league average, shrunk toward 1.0 with a 12–14 game prior, then multiplied with a 6% home edge. A Poisson score matrix gives the money line, puck line and total.
  • Baseball. The same Poisson construction on team runs scored and allowed per game from the MLB Stats API season splits, with a 2% park/home adjustment.
  • Basketball. Expected points from season-to-date points for/against per game, margin as a Normal with sigma 10.5 and totals with sigma 12.
  • Handball and Volleyball. Attack/defence from the official league table; Poisson for handball, set-ratio and point-ratio logistic for volleyball, converted to a per-set probability to price the set handicap and total sets.
  • Tennis. Seeding implies a ranking slot (seed n ≈ rank 2n−1, unseeded ≈ 45–55), mapped to an Elo via 2200 − 100·ln(rank). Seed-only inputs are capped at Medium.
  • Motor Racing. Race-winner probabilities are a softmax over official championship points with a 55-point temperature.

3. Grading

High ≥ 70%, Medium 58–70%, Low below 58%, with sample caps. The pick column on each row is the match winner; the pick table also shows the strongest selection across every market we originated.

4. What is deliberately blank

No value is inferred. A row with no official form feed keeps an empty price and an explicit flag. Injury information is only ever stated when an official page carries it, which is why no prediction claims an injury in this build.
